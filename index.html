Award-winning

Student Subject Scheduling and Faculty Loading System

PHP 8.2Laravel 12Livewire 3BreezeSpatie PermissionMySQL 8BladeTailwindAlpine.jsDomPDFVite 7
  • A capstone platform for Granby Colleges of Science and Technology that handles the whole academic cycle, from account registration to finalized, graded class schedules, across four roles: Super Admin, Program Admin, Teacher and Student.
  • The scheduling engine automatically builds conflict-free schedules, then re-checks everything inside a database transaction before committing — old meeting records only get replaced once the new schedule actually passes.
  • Winner of the Outstanding System Development Award, AY 2025–2026, and presented at the institution’s thesis symposium.
10 modules · 11 scheduling safeguards

Authentication & Account Approval

Registration with academic data and up to 10 private PDF uploads; pending / active / inactive / declined states with reviewer notes and full approval history; email notifications on decisions; automatic academic-record creation and placement into the least-filled eligible section on approval.

Programs, Subjects & Curriculum

Programs with configurable duration and term count. Curricula versioned by effective date and organised by year level, term and sequence — required, elective, major, minor, general, thesis and internship subjects with units, prerequisites and minimum grades.

Section Management

Sections scoped to a program and curriculum with capacity and status; student transfer between compatible sections; term promotion blocked while offerings are still open; archive and restore limited to empty or fully-graduated sections.

Faculty Availability & Load

Day and time availability per teacher, regular (36-unit) versus part-time (20-unit) load ceilings enforced automatically, three-tier subject preference ranking, and program-scoped permissions for Program Admins.

Schedule Generation Engine

Given a section, evaluates every required subject in its curriculum term and builds a conflict-free schedule. Cross-checks subject duration, teacher preference and program, availability windows, current load against the ceiling, existing teacher / room / section conflicts, room availability, and other rows in the same unsaved draft. Prefers ranked teachers, falls back to same-program teachers, and flags incomplete rows for manual review.

Class Offering Management

Manual create, edit and reschedule with live teacher and room availability lookups; archive, cancel, unlock and reactivate depending on offering state; per-section and consolidated PDF export.

Enrollment & Curriculum Tracking

Curriculum-driven subject initialisation with custom subjects for irregular and transfer students; per-subject status (not taken / enrolled / passed / failed / credited); duplicate-enrollment, prerequisite and schedule-overlap enforcement; enrollment history and change notifications.

Teacher Portal

Today's classes, next class, weekly teaching time and pending evaluations; weekly and monthly load summaries, class rosters, grade entry with a finalisation lock, and A4 PDF schedule export.

Student Portal

Section schedule merged with additional enrolled classes, curriculum progress view, schedule history and A4 PDF export.

Dashboards & Reporting

Role-scoped counts — students by status, pending approvals, active teachers, sections and rooms, enrollment by program, yearly trends — plus printable section, teacher, student and consolidated reports.

Full-Stack Developer Portfolio

Laravel 13React 19ViteSanctumPostgreSQLSupabaseDockerRenderAxios
  • A React 19 + Vite front end on top of a Laravel 13 REST API, with a Sanctum-authenticated admin dashboard so I can edit projects and profile content without touching code.
  • The public GET /api/projects endpoint serves published, ordered projects, while create, update and delete all sit behind auth:sanctum. SPA auth uses Sanctum’s stateful session cookies instead of bearer tokens, with CSRF protection and session regeneration on login.
  • Supabase-hosted PostgreSQL through the session pooler over SSL, with admin credentials seeded from environment config — never from source control.
  • Shipped as a single Docker image on Render, serving the built React app and the API from one origin so the cookie auth never runs into cross-site restrictions. Backend feature tests run on an isolated in-memory SQLite database.

Backend API

Restaurant Order API

C#.NET 8ASP.NET CoreEF CoreSQLitexUnitSwagger
  • A REST API covering a restaurant’s full order flow — menu, cart, checkout and receipts — built to keep a C#/.NET track going alongside the Laravel work.
  • Order lines snapshot the menu price at the moment they’re added, so a later price change can never rewrite a placed order’s total. Deleting a referenced menu item retires it instead of hard-deleting it, so historical orders stay intact.
  • An order can only be paid once — it records the method and timestamp, and paid orders become immutable.
  • EF Core migrations run on startup with seed data, Swagger UI is available in development, and an xUnit suite covers order-total math plus the cart / pay / receipt rules using EF Core InMemory.
